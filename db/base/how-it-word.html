全局概览

核心组件

  • 进程管理器：为了实现纳秒级操作，一些现代数据库使用自己的线程
  • 网络管理器：对于分布式数据库来说网路I/O是个大问题
  • 文件系统管理器：磁盘I/O是数据库的首要瓶颈
  • 内存管理器：为了避免磁盘I/O带来的性能随时，需要大量的内存
  • 安全管理器：用于对用户的验证和授权
  • 客户端管理器：用于管理客户端连接

工具

  • 备份管理器：用于备份和恢复数据
  • 恢复管理器：用于崩溃后重启数据库到一个抑制状态
  • 监控管理器：用于记录数据库活动信息和提供监控数据库的工具
  • 管理员管理器：用于保存元数据（比如表的名称和结构），提供管理数据库、模式、表空间的工具

查询管理器

  • 查询解析器
  • 查询重写器
  • 查询优化器
  • 查询执行器

数据管理器

  • 事务管理器：用于管理事务的提交、回滚、恢复等操作
  • 缓冲管理器：用于缓存数据，提高数据库的性能
  • 数据访问管理器：访问磁盘中的数据

数据查询的流程

客户端管理器

  1. 首先检查用户的验证信息（用户名和密码），然后检查用户是否有访问数据库的权限
  2. 检查是否有空闲进程（或线程）来处理查询请求
  3. 检查数据库是否负载很重
  4. 可能会等待一会儿来获取需要的资源。如果等待时间达到超时时间，它会关闭连接并给出一个可读的错误信息。
  5. 把你的查询送给查询管理器来处理
  6. 一旦它从查询管理器得到数据，它会把部分结果保存到一个缓冲区并且开始给你发送
  7. 如果遇到问题，管理器关闭连接，向你发送可读的解释信息，然后释放资源。

查询管理器

  1. 查询解析器解析查询，判断是否合法
  2. 查询重写器重写查询，去除了无用的操作并且加入预优化部分
  3. 查询优化器优化查询，并转换为可执行代码和数据访问计划
  4. 查询执行器编译计划：生成执行计划，包括物理执行计划和物理数据访问计划MySQL
  5. 查询执行器执行查询，并把结果返回给客户端管理器

提示

在MySQL架构中，编译计划主要属于执行器的工作范畴，但与优化器有紧密协作： 优化器的贡献：

  1. 生成逻辑执行计划
  2. 确定操作符组合方式 执行器的主体工作：
  3. 物理执行计划实例化
  4. 运行时参数绑定
  5. 代码生成

优化器决定了执行策略，但真正的"编译"工作（将策略转换为可执行代码）主要由执行器完成。这种分离保持了优化器的独立性，同时允许执行器进行特定运行时优化。

查询解析器

  1. 检查关键字是否正确，比如WHERE写在SELECT之前会被拒绝
  2. 使用数据库元数据检查表和字段，例如表和字段是否存在，对某类型字段的运算是否可能
  3. 检查是否有权限读取（或写入）表
  4. 解析结束后，SQL查询被转换为内部表示

查询重写器

重写器的目标是：

  • 预优化查询
  • 避免不必要的运算
  • 帮助优化器找到合理的最佳解决方案

重写器按照一系列已知的规则对查询执行检测，若匹配到某种规则，则对查询进行重写。

  • 视图合并：视图会转换为它的SQL定义，并在查询中替换掉
  • 子查询扁平化：子查询是很难优化的，因此重写器会尝试移除子查询
  • 去除不必要的运算符：比如你用了DISTINCT，但其实有UNIQUE约束，重写器会自动去掉DISTINCT
  • 排除冗余的连接：如果相同的JOIN条件出现了两次，就会被消除
  • 常数计算赋值
  • 分区裁剪：如果使用了分区，重写器能够找到需要使用的分区
  • 物化视图重写：
  • 自定义规则

提示

在MySQL架构中，子查询展开主要属于查询优化器的工作范畴，但重写器会参与前期准备

  1. 基础预处理（sql/sql_resolver.cc）
  2. 标记子查询类型（相关/非相关）
  3. 简单语法转换（如IN→EXISTS）
  4. 识别可展开的子查询模式
  5. 视图合并准备（sql/sql_derived.cc） 查询优化器的主体工作:
  6. 核心展开逻辑
  7. 成本决策
  8. 评估物化 vs 展开的成本
  9. 处理相关子查询的特殊情况

提示

缓存管理器

数据库的主要瓶颈是磁盘 I/O。为了提高性能，现代数据库使用缓存管理器。 查询执行器不会直接从文件系统拿数据，而是向缓存管理器要。缓存管理器有一个内存缓存区，叫做缓冲池，从内存读取数据显著地提升数据库性能。

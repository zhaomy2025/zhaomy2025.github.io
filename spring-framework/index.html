Spring 是构建于 Java 平台之上的开源容器框架，用 IoC 管理对象的创建与装配、用 AOP 抽离横切逻辑，主要目的是简化 Java 企业级应用的开发。

本组文章以 Spring Framework 6.x 为主；引用更早或更新版本的篇章，正文里各有版本标注。

Spring概述

什么是 Spring？

Spring 是构建于 Java 平台之上的开源容器框架：用 IoC 管理对象的创建与装配，用 AOP 抽离横切逻辑。

Spring 的主要目的是什么？

简化 Java 企业级应用的开发。

Spring 有哪些特性？

控制反转（IoC）把对象的创建权交给容器管理；依赖注入（DI）把对象之间的依赖关系交给容器装配，不必手动 set；面向切面编程（AOP）把日志、事务、权限校验这类每个方法都要做、又跟业务无关的逻辑，从业务代码里抽出来集中到切面，由框架在方法调用时自动织入，业务代码里看不到这些逻辑；容器还提供声明式事务、消息等服务，以及 JdbcTemplate、与 Hibernate/JPA/Struts 集成等辅助能力，用来加快应用开发。

Spring 的核心是什么？

IoC 和 AOP。下面给出 IoC 和 AOP 的常见问题，可以先思考一下，在后面章节再详细介绍。

IoC（Inversion of Control）

如何理解 IoC？

IoC 是控制反转（Inversion of Control）：对象的创建权不再由代码自己 new，而是交给容器——容器负责创建对象，并把对象之间的依赖装配好，从而降低对象之间的耦合。

IoC 和 DI 的关系？

IoC 是设计思想，DI 是实现方式：IoC 指对象的创建和依赖关系交给容器管，DI 指容器把某个 Bean 需要的其他 Bean 注入进去。IoC 是目的，DI 是达成它的手段，两者是同一件事的两面。

IoC 配置有哪三种方式？

XML 配置、Java 配置类、注解配置。注解配置在组件类上标 @Component，再用 @ComponentScan 指定扫描范围；Java 配置类用 @Configuration + @Bean 定义外部 Bean；XML 配置通过 @ImportResource 引入 XML 文件，正逐步淘汰。

依赖注入有哪三种方式？

构造器注入、Setter 注入、字段注入。强制依赖用构造器注入，可选依赖用 Setter 注入，避免字段注入。

为什么推荐构造器注入？

构造器注入保证对象一创建出来，必需的依赖就都已就位，不会出现「用到了某个依赖却还没注入」的中间状态；依赖可以声明成 final，也便于在单元测试里直接 new 出对象、手动传入依赖。

构造器注入太多类导致 bad smell，怎么解决？

构造器参数过多，通常说明这个类承担的职责太多，先按职责把它拆小；如果确实是在组合多个协作者，可以借助 Lombok 的 @RequiredArgsConstructor 之类减少样板代码，但拆分类职责才是根本解法。

@Autowired、@Resource 和 @Inject 有什么区别？

@Autowired（Spring）可用于字段、构造器、方法，按类型注入，遇到多个同类型 Bean 时配合 @Qualifier 或 @Primary；@Inject（JSR-330）用法类似、按类型注入，用 @Named 限定；@Resource（JSR-250）默认按名称注入，找不到同名 Bean 再按类型，用 name 属性指定 Bean 名称。

IoC 配置的三种方式和依赖注入的三种方式如何对应？

IoC 配置管「怎么定义和组装 Bean」，依赖注入管「怎么把依赖交给目标 Bean」，可以认为依赖注入是 IoC 配置的一部分，不同配置方式支持的注入方式不同：XML 配置支持构造器注入和 Setter 注入；Java 配置类通常用构造器注入（@Configuration + @Bean + 方法参数）；注解配置可以指定任一种注入方式（构造器 / Setter / 字段）。

Spring IoC 的实现原理？

工厂模式 + 反射机制：工厂模式负责按容器配置统一创建和管理对象，反射机制负责在运行时按配置元数据决定实例化哪个类、调用哪个构造器、注入哪些依赖。

Spring IoC 的体系结构？

从接口层看：BeanFactory 定义容器的基本功能，BeanDefinition 描述 Bean 及其依赖关系，BeanDefinitionRegistry 存放这些定义，ApplicationContext 在它们之上叠加容器级功能（事件发布、国际化、资源加载等）。

Spring IoC 的初始化流程？

分两步：先把配置（XML、注解、Java 配置类）解析成一批 BeanDefinition——描述 Bean 及其依赖的「图纸」，再按定义实例化 Bean。ApplicationContext 的入口是 refresh()，最后由 finishBeanFactoryInitialization() 实例化所有非懒加载的单例；BeanFactory 则懒加载，在 getBean() 时才创建。

Bean 的生命周期？

实例化 → 属性填充 → 初始化 → 使用 → 销毁，中间穿插后置处理器的回调：InstantiationAwareBeanPostProcessor 在实例化前后、BeanPostProcessor 在初始化前后（@PostConstruct 属初始化前）；Bean 自身也可以实现 InitializingBean / DisposableBean，或声明 init-method / destroy-method 来插手。

AOP（Aspect-Oriented Programming）

如何理解 AOP？

AOP（Aspect-Oriented Programming，面向切面编程）：把日志、事务、权限校验这类每个方法都要做、又跟业务无关的逻辑，从业务代码里抽出来集中到切面，由框架在方法调用时自动织入，业务代码里看不到这些逻辑。

AOP 的核心术语有哪些？

连接点 JoinPoint（Spring AOP 里就是方法的执行）、切点 PointCut（匹配连接点的条件）、通知 Advice（在连接点做什么、何时做）、切面 Aspect（切点 + 通知）、目标对象 Target（执行业务逻辑的对象）、代理 AOP Proxy、织入 Weaving（把切面应用到目标对象的过程）。

AOP 有哪些实现方式？

分静态代理和动态代理两大类：静态代理在编译 / 类加载阶段生成代理类，也叫编译时增强；动态代理在运行时于内存中临时生成代理类，也叫运行时增强。

Spring AOP 的两种动态代理有什么区别？

Spring 默认按目标对象有没有实现接口来选：实现了接口就用 JDK 动态代理（java.lang.reflect.Proxy，更松耦合）；没有实现接口就用 CGLIB 生成目标对象的子类（不要求接口，耦合性略差）。Spring Boot 默认一律走 CGLIB。

Spring AOP 有哪两种配置方式？

XML 配置（用 aop:config、aop:aspect、aop:pointcut、aop:before 等命名空间标签声明切面、切点和通知）和基于 @AspectJ 的注解方式（用 @Aspect、@Pointcut、@Before 等注解）。

切点表达式 execution 的语法是什么？

execution(modifiers-pattern? ret-type-pattern declaring-type-pattern? name-pattern(param-pattern) throws-pattern?)，其中返回类型、方法名、参数列表必填，其余可省略。常用通配符：* 匹配任意字符，.. 匹配当前包及其子包或任意数量参数，+ 匹配指定类型及其子类型，! 表示逻辑非。

Spring AOP 和 AspectJ 有什么区别？

AspectJ 需要特殊编译器，支持编译时、编译后和加载时织入，能作用于字段、构造器、静态初始化等多种连接点，也可作用于所有域对象；Spring AOP 基于运行期动态代理，只织入方法执行的连接点，作用对象是容器管理的 Bean，不需要特殊编译器。

Spring有哪些组件？

核心容器

Beans：提供了框架的基础部分，包括控制反转和依赖注入。 BeanFactory 接口是Beans模块的核心接口。
Core：封装了 Spring 框架的底层部分，包括资源访问、类型转换及一些常用工具类。
Context：集成 Beans 模块功能并添加资源绑定、数据验证、消息资源处理（国际化）、Java EE 支持、容器生命周期、事件传播等。ApplicationContext 接口是上下文模块的焦点。
Context-Support：把缓存、邮件、调度、模板引擎这类第三方库集成进 Spring 上下文。
SpEL：提供了强大的表达式语言，支持访问和修改属性值、对象方法调用，支持从 Spring IoC 容器中获取对象。

数据访问/集成

  1. JDBC (Java Database Connectivity)：提供了JDBC的样例模板，能消除传统冗长的 JDBC 编码还有必须的事务控制，简化了对关系数据库的访问。
  2. ORM (Object Relational Mapping)：提供与ORM框架无缝集成的API，支持 JPA、Hibernate 等。JPA 是一个 Java 持久化 API。
  3. OXM (Object XML Mappers)：提供了一个支持 Object /XML 映射的抽象层实现，如 JAXB、Castor、XMLBeans、JiBX 和 XStream。用来将 Java 对象映射成 XML 数据，或者将XML 数据映射成 Java 对象，有时候也称为 XML 的序列化和反序列化。用的比较少，了解下即可。
  4. JMS: 指 Java 消息服务，提供一套 “消息生产者、消息消费者”模板用于更加简单的使用 JMS，JMS 用于用于在两个应用程序之间，或分布式系统中发送消息，进行异步通信。
  5. Transaction：简单而强大的事务管理功能，包括声明式事务和编程式事务。

Web

  1. Web 模块：提供了基本的 Web 开发集成特性，例如多文件上传功能、使用的 Servlet 监听器的 IoC 容器初始化以及 Web 应用上下文。
  2. Servlet：提供了一个 Spring MVC Web 框架实现。Spring MVC 框架提供了基于注解的请求资源注入、更简单的数据绑定、数据验证等及一套非常易用的 JSP 标签，完全无缝与 Spring 其他技术协作。
  3. WebSocket：Spring 4.0 引入了对 WebSocket 的支持，用户只要实现响应的接口就可以快速的搭建 WebSocket Server，从而实现双向通讯。
  4. WebFlux：Spring Framework 5.x中引入的新的响应式web框架。与Spring MVC不同，它不需要Servlet API，是完全异步且非阻塞的，并且通过Reactor项目实现了Reactive Streams规范。Spring WebFlux 用于创建基于事件循环执行模型的完全异步且非阻塞的应用程序。

AOP、Aspects、Instrumentation和Messaging

  1. AOP：提供了面向切面编程实现，提供比如日志记录、权限控制、性能统计等通用功能和业务逻辑分离的技术，并且能动态的把这些功能添加到需要的代码中，这样各司其职，降低业务逻辑和通用功能的耦合。
  2. Aspects：提供与 AspectJ 的集成，是一个功能强大且成熟的面向切面编程（AOP）框架。
  3. Instrumentation：该层为类检测和类加载器实现提供支持。用的比较少，了解下即可。
  4. Messaging 模块：Spring 4.0 引入了消息（Spring-messaging）模块，该模块提供了对消息传递体系结构和协议的支持。
  5. Jcl： Spring 5.x中新增了日志框架集成的模块。

Test

  1. Spring Test：提供了对 JUnit 和 TestNG 测试框架的支持，包括 Spring 的测试上下文、Spring MVC 测试、WebFlux 测试等，还提供了一些基于 Spring 的测试功能，比如在测试 Web 框架时，模拟 Http 请求的功能。

Spring中有哪些设计模式？

Spring的设计模式主要有工厂模式、模板模式、观察者模式、适配器模式、代理模式。这些设计模式应用于不同的场景，比如BeanFactory用于实例化对象，模板模式用于简化代码，观察者模式用于事件驱动，适配器模式用于 Spring MVC，代理模式用于AOP。但这些设计模式的实现方式是有共性的，都是基于封装、继承、多态三大特性来实现的。

工厂模式、模板模式、观察者模式都是在接口/父类中定义了一些通用的方法，子类可以根据需要重写这些方法，从而实现不同的功能。例如工厂模式覆盖了创建对象的过程，模板模式重写了算法的部分步骤，观察者模式重写了接收通知后的处理过程。

适配器模式的实现方式是通过继承或组合的方式，将一个类的接口转换成客户希望的另一个接口。

代理模式的实现方式是在运行期生成代理对象包裹目标对象：目标实现了接口时用 JDK 动态代理，没有实现接口时用 CGLIB 生成子类，代理在转发调用前后插入通知逻辑。

工厂模式

Spring中有很多地方使用了工厂模式，比如BeanFactory、ApplicationContext等。BeanFactory是Spring的核心接口，它负责实例化、定位、配置应用程序中的对象，实现类有 XmlBeanFactory（自 Spring 3.1 起已废弃，Spring 6 中已删除）、DefaultListableBeanFactory 等。

模板模式

模板模式是一种行为型设计模式，它定义一个操作中的算法的骨架，而将一些步骤延迟到子类中。模板方法使得子类可以不改变一个算法的结构即可重定义该算法的某些特定步骤。 Spring中有很多地方使用了模板模式，比如JdbcTemplate、HibernateTemplate、RedisTemplate等。

观察者模式

观察者模式定义了对象之间的一对多依赖，当对象改变状态时，依赖它的对象会收到通知并自动更新。Spring的事件驱动模型就是观察者模式的应用。 Spring中有很多地方使用了观察者模式，比如ApplicationEvent、ApplicationListener、MessageSource等。

适配器模式

适配器模式将一个类的接口转换成客户希望的另一个接口，使得原本由于接口不兼容而不能一起工作的两个类可以一起工作。

  • Spring AOP 的通知适配：AdvisorAdapter 把不同类型的通知适配成统一的调用形式。
  • Spring MVC的适配器模式：HandlerAdapter接口用于适配处理器（Controller 等）的请求

代理模式

代理模式为目标对象提供一个代理对象，由代理对象控制对目标对象的访问，并在调用目标方法前后附加额外处理。 Spring AOP 的核心就是代理模式：容器返回给调用方的是代理对象，方法调用先进入代理，通知逻辑在代理里执行完再转发给目标对象。

Bootstrap 简介

一句话

Bootstrap 是把「响应式栅格 + 预制组件」普及开来的奠基级前端 UI 框架；它的 class 驱动 + jQuery 插件范式已被现代组件库和 Tailwind 取代，但海量存量后台系统里仍绕不开。

是什么

Bootstrap 是一套由 Twitter 团队开源的前端 UI 框架（HTML / CSS / JS 组件库），2011 年发布。它让开发者不用从零写样式，下载引入就能得到一套统一、响应式的页面外观。核心是三件套：

  • 栅格系统（Grid）：用 .row + .col-*-* 把页面切成 12 列响应式布局，手机 / 平板 / 桌面自动适配。这是它对前端最大的贡献。
  • 预制组件：按钮、表单、导航栏、卡片、模态框、表格、分页等，加 class 即有效果。
  • 工具类（Utilities）：mt-3（外边距）、text-center、d-flex 这类原子类快速调样式。
  • JS 插件：下拉、弹窗、轮播、提示框等交互，早期依赖 jQuery，Bootstrap 5 已彻底移除 jQuery 依赖。

版本简史（关键分水岭）

版本年份关键变化
2.x2012早期栅格，兼容 IE7+
3.x2013移动优先重构，栅格重做，最经典、存量最多（大量 Ace Admin 类后台模板基于它）
4.x2018改用 Flexbox 栅格，Sass 重写，放弃 IE9-
5.x2021去掉 jQuery，纯原生 JS；新增 RTL、CSS 变量、离线粒子等

3.x 是最经典的一代：很多 2015–2020 年的企业 / 政府 / 金融后台都基于 Bootstrap 3 模板搭建，至今仍在维护。

核心概念

  • 12 列栅格：一行 .row 内放若干 .col-md-6 等，总宽按 12 等分。配合断点前缀（xs/sm/md/lg/xl）实现不同屏幕不同布局。
  • 响应式断点：以视口宽度为阈值切换样式，移动优先（默认手机样式，再向上增强）。
  • 组件 + 工具类双层：大块结构用组件 class，细节微调用工具类，减少自定义 CSS。
  • JS 插件与 jQuery：Bootstrap 3/4 的弹窗、下拉等靠 jQuery 选择器 + 事件绑定驱动；这和 AngularJS / Vue 的「声明式渲染、框架管 DOM」范式天然冲突——插件在元素被框架插入 DOM 之前扫描就找不到目标（典型的「动态 DOM 漏初始化」坑，详见本站 AngularJS 生命周期一文）。

和「上古后台模板」的关系

你在本站看到的 Ace Admin 模板简介，其底座就是 Bootstrap 3 + jQuery。这类模板在「组件化框架」普及之前是后台开发的主流：下载 HTML 改改就能用。

但时代变化后，它的范式成了负担：

  • jQuery 命令式操作 DOM，与 AngularJS / React / Vue 的声明式生命周期错位；
  • 预制组件固定，想深度定制要覆盖大量变量，不如 Tailwind / CSS-in-JS 灵活。

所以这类系统今天的价值主要是「维护存量时的踩坑参考」，而非新项目的选型目标。

为什么热度下降

  1. Utility-first 崛起：Tailwind CSS 用原子类组合样式，比 Bootstrap 的「预制组件套 class」更灵活、不绑死设计语言，新项目更爱用。
  2. 组件库自带样式：Vue / React 时代，Element Plus、Ant Design 把布局 + 组件 + 主题全包了，通常不需要再引 Bootstrap 做底座。
  3. 定制成本高：Bootstrap 想改主题色 / 圆角得覆盖大量 Sass 变量或手写大量覆盖样式，不如新方案顺手。

现在还值得用吗

场景建议
新中后台项目直接用 Element Plus / Ant Design 等组件库，一般不单独引 Bootstrap
通用 / 静态站点想快速出带样式的页面、又不想引组件库，Bootstrap 5（无 jQuery）仍是最省事方案之一
维护存量系统大量 2015–2020 后台基于 Bootstrap 3/4，绕不开，当「踩坑参考」即可

提醒

  • 新项目别再基于 Bootstrap 3 + jQuery 模板（如 Ace Admin）起步，它和现代框架生命周期冲突、维护成本高。
  • 若要用 Bootstrap，优先 5.x（已去 jQuery）；4.x 尚可，3.x 已不建议新引入。
  • 选型上，中后台闭眼组件库，轻量通用页可 Tailwind 或 Bootstrap 5，三者不必混用。

小结

Bootstrap 是响应式栅格与预制组件的开创者，定义了「移动优先」的页面范式；随着 Tailwind 与组件库兴起，它作为「新项目底座」的角色退场，但在存量系统里仍极常见。理解它，主要价值在于维护和排查那批 jQuery 时代的老后台。
